# The audit of Lapin's public edition, 15.11.2026

The edition audited: `lapin` (`products/lapin.json`, its 20 modules), on `origin/main` at `d6916d92`.

What was looked for: bugs, duplicated code and functions, tools that overlap, and advanced tools that could replace the simple ones.

How it was done: five parallel analyses that read the code (the modelling modules, the platform, the engine's duplicates, the interface, the tool inventory). Nothing was changed in the repo. The application was not started and tried by hand, so the report does not cover what only shows in use (speed, the feel of gestures, display).

How sure the findings are:
- **Confirmed by a test**: a temporary test reproduced the problem (and was then deleted).
- **Rechecked**: I reread the code after the analysis, and it is confirmed.
- **Read**: the analysis followed the path through the code, without a test. Each has its file and line, so it is easy to check before fixing.

Engine paths are relative to `engine/src/`, interface paths to `ui/src/`.

## 1. In short

- **I found no bug that breaks or loses data on an ordinary path.** Saving, checking the parts on opening, undoing a failed command and guest access are done correctly.
- **I found 70 bugs**: 6 serious, the rest medium and small. The serious ones are in section 2.
- **Three recurring causes explain almost half of the engine's bugs.** Fixed at the root, each closes a whole class (section 3).
- **The most dangerous duplicated code is where the copies no longer do the same thing**: two steel profile catalogues, ten number readers, five filter engines (section 5).
- **For the user, the application has too many tools that do almost the same thing**: about 22 schedule buttons, two clash windows, separate "straight" and "curved" tools, about 75 furniture and MEP buttons that are the same tool (section 6).

## 3. Three recurring causes

**a) Links between elements are not rebuilt on copying and not cleaned up on deleting.** Copying a storey rebuilds them; an ordinary copy, mirror or array does not. This gives:
- a copied roof's downpipes double up on the original roof (`Roofs/RoofEdges.cs:110`);
- a copied stair gets no opening in the slab, and a moved one leaves it in the old place (`Stairs/StairBuilder.cs:509`);
- walls tied to a roof stay tied to the original (`Roofs/RoofTop.cs:45`);
- the space under a stair stays under the original stair (`Stairs/UnderStairs.cs:90`);
- a mirrored L or U stair is not the mirror image (`StairBuilder.cs:93`);
- steel connections are left hanging when the hall is deleted (`Steel/NodeCommands.cs:90`);
- bars are left with no host when the reinforced element is deleted (`Rebar/RebarModule.cs:875`);
- plus G2 and G3.

The root fix: one rebuild of the links in the general copy (`Placement.DeepCopy`), by the map of copies, and one deletion rule per link.

**b) The text "NaN" is accepted as a number and passes the range checks.** `Json.Number` (`Model/Lapin.Model/Entity.cs:71`) reads "NaN" and "Infinity", and checks written as `x < min || x > max` let them through. About 12 places: the clash tolerance (every clash is missed silently), timber frames (no studs), rebar. The root fix: `Json.Number` refuses non-finite values.

**c) Sizes, spacings and repetition counts with no limit.** Besides G4: contours on a flat terrain with a tiny interval (`Civil/Tin.cs:304`), planting zones with over a billion checks (`Civil/Plantings.cs:124`), previews of a huge length that ask for 8 GB (`SiteWorks/Common.cs:105`, `Wood/WoodModule.cs:112,175`).

## 7. Suggestions, in order

1. **The serious fixes and the three recurring causes.** G1–G6, then rebuilding links on copy, refusing non-finite values in `Json.Number`, and limits on spacings and counts. They are small in volume and close about 20 bugs.
2. **Four shared components in the interface**: `ColourField`, `Dialog`, `prompts.ts`, the shared number fields. They fix G5 and U1–U3, U9, U10.
3. **The medium platform bugs**: P1–P6. P2–P4 are each a `catch` or a check.
4. **One profile catalogue, one number reader, one CSV module** (D1, D2, D7). D1 needs an upgrade of the projects that hold only the profile's name.
5. **A single filter engine** (D3, D4, S10). It is the riskiest unification: saved filters must keep their meaning, so it comes with a project upgrade and with tests on each of today's differences.
6. **Simplifying the ribbon, with no change to the model**: S13, S5, S3, S8, S2. The tools' identifiers stay as aliases, so shortcuts and "My tools" keep working.
7. **The fixed schedules as templates** (S1), then the source of pieces.
8. **In the long term**: outlines with arcs and holes (S4), parts as the only parametric object (S6), CAD edits on elements, annotations on sheets, the shared 2D board (S11).

The clean-up (unused code, the geometry helpers, D8–D13) can be done at any time, in small batches, with the tests as the safety net.

## 8. What the audit does not cover

- The application was not run: nothing about speed, display, the feel of gestures or errors visible only in use.
- Walls, joins, layers, slabs and openings were checked only by sampling.
- The premium editions and the modules in private repos were not touched.
- The translations were not checked as language.
- About 60 suspicions were set aside because they were not confirmed on reading.
